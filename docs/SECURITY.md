# Security model

FloodGrid is an educational prototype, but it is built the way a small
production system should be built: server-side secrets, hashed credentials,
auditable privileged actions and least privilege by default. This document
records what is implemented and what an operator must still do.

## Threat model (prototype scope)

| Asset | Protection |
| --- | --- |
| Account passwords | bcrypt, cost 12, with a policy of at least 10 characters. Legacy scrypt hashes are still verified and upgraded on next login. Failed sign-ins are counted and the account is locked for a few minutes after too many. |
| Session cookies | http-only, `SameSite=Lax`, server-side session records with a TTL, revocable individually. |
| CSRF | A per-session token required in `x-csrf-token` on every state-changing request, plus an origin check. |
| Device API keys | 192-bit random keys, stored only as SHA-256 hashes, shown once at provisioning, rotatable and revocable. |
| Provider credentials (SMTP, SMS) | AES-256-GCM encrypted at rest with `SETTINGS_ENCRYPTION_KEY`, never returned to the browser, never logged. |
| TOTP secrets | AES-256-GCM encrypted at rest. |
| Rotating ops credential | Single-use, hashed, short lived, rate limited, delivered by email only. |
| Secrets at rest | Provider credentials and TOTP secrets are AES-256-GCM encrypted with `SETTINGS_ENCRYPTION_KEY`; the key never leaves the server. |
| Flood telemetry integrity | Monotonic sequence numbers per device; replays are rejected with `409`. |
| Barrier commands | Unique command id, single-use nonce, 120 s expiry, idempotent acknowledgement, full audit trail. |
| Privileged actions | Role + scope checks on the server for every route; CIDR allowlists for admin, ops and device ingress. |

## Server-side secrets only

`server/config.ts` is the only place environment variables are read. The browser
receives `publicConfig()`, which contains the app name, the database mode,
whether Web Push is configured, the VAPID **public** key, the Cloudinary cloud
name and upload preset, the MQTT flag and the configured firmware links.

Nothing else is ever sent to the client: no SMTP password, no SMS gateway
credential, no Cloudinary API secret, no Turso token, no device key, no ops
credential. The frontend never receives a value it could use to authenticate as
someone else.

## The rotating operations credential

`/hackeradmin` is the super-admin operations console. It does not use the normal
login form.

1. A credential is generated by the server and **emailed** to
   `OPS_SECURITY_EMAIL`.
2. Only a SHA-256 hash is stored. The plaintext exists in memory for the length
   of one request and nowhere else.
3. The credential is single-use: consuming it invalidates it immediately.
4. It expires after `OPS_CREDENTIAL_TTL_MINUTES` (75 by default) and is rotated
   every `OPS_ROTATION_MINUTES` (60 by default).
5. Attempts are limited to `OPS_MAX_ATTEMPTS` (5) per rotation window.
6. `OPS_REQUIRE_MFA=true` additionally requires a TOTP code.
7. Ops routes are restricted to `OPS_CIDR_ALLOWLIST` (falling back to
   `ADMIN_CIDR_ALLOWLIST`) and the ops session lasts
   `OPS_SESSION_TTL_MINUTES` (30).

The credential is **never** placed in a URL, a query string, a response body,
browser source, frontend JavaScript, a log line or an error message. Rotation
happens automatically in a background timer and can be triggered manually from
the console; the new value is emailed, never displayed after the fact.

## Roles and scoping

| Role | Can do |
| --- | --- |
| `MEMBER` | See the public status page and their own dashboard, alerts and profile. |
| `OPERATOR` | Everything a member can, plus issue barrier commands for their zone. |
| `ADMIN` | Local administrator: devices, policies, users, settings and pages **within their city/zone**. |
| `OWNER` | Super administrator: every scope, plus the ops console. |

`inAdminScope()` is applied on the server for every scoped route, so a local
admin cannot read or modify another city even by guessing an id. Device
registration additionally requires a verified TOTP code.

The first `OWNER` is created only through `POST /api/auth/bootstrap` with
`OWNER_BOOTSTRAP_TOKEN` (32+ random characters) from an IP inside
`ADMIN_CIDR_ALLOWLIST`. Bootstrap closes permanently once an OWNER exists, and
there is no default account, default password or demo owner.

## Network controls

| Allowlist | Applies to | Empty in production |
| --- | --- | --- |
| `ADMIN_CIDR_ALLOWLIST` | Admin routes and owner bootstrap | Denied (fail closed) |
| `OPS_CIDR_ALLOWLIST` | Ops console routes | Falls back to the admin list |
| `DEVICE_CIDR_ALLOWLIST` | Device telemetry and commands | Denied (fail closed) |

`TRUST_PROXY` must match the number of proxy hops in front of the app (1 on
Render) or client IP resolution — and therefore every allowlist — is wrong.

## HTTP hardening

Applied to every response:

- `Content-Security-Policy`: `default-src 'self'`, `object-src 'none'`,
  `base-uri 'self'`, `form-action 'self'`, `frame-ancestors 'none'`,
  `upgrade-insecure-requests`. Styles allow `unsafe-inline` because React
  components use inline style objects; scripts are `'self'` only.
- `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`,
  `Referrer-Policy: strict-origin-when-cross-origin`, `Permissions-Policy`
  disabling camera, microphone, geolocation and payment, plus COOP/CORP.
- `Strict-Transport-Security: max-age=31536000; includeSubDomains`.
- JSON bodies capped at 32 KB, URL-encoded at 16 KB.
- `x-powered-by` disabled.
- Rate limits: 400/min on `/api/*`, 600/min on telemetry, and tighter limits on
  login, registration, password reset, TOTP, provisioning and command
  acknowledgement.

Web Push endpoints are validated against an allowlist of known push services
before a subscription is stored, which blocks server-side request forgery
through a crafted `endpoint`.

## Data integrity

- **Duplicate events**: flood events carry `device:seq:state` as a unique key, so
  a replayed sample cannot create a second event.
- **Duplicate notifications**: the delivery queue has a unique
  `(channel, recipient, event_id)` index.
- **Idempotent acknowledgements**: acknowledging a command twice returns the
  same record and never re-executes the action.
- **Audit log**: device registration, approval, enable/disable, credential
  rotation and revocation, flood state transitions, barrier command issue /
  delivery / acknowledgement / cancel / expire, login, logout, password change,
  MFA enrolment and reset, role and scope changes, provider updates, settings
  and flag changes, maintenance mode, ops sessions and backups. Each record
  stores actor, target, metadata, IP and timestamp.

## Privacy

- IP geolocation is an **advisory hint only** during registration. Eligibility
  is decided by the service-area allowlist, never by IP location. If
  `IP_GEO_LOOKUP_URL` is empty, no lookup happens.
- Public email subscriptions use double opt-in: a confirmation email, then a
  hashed unsubscribe token. Every bulk email carries an unsubscribe link.
- Push subscriptions are stored per user with consent timestamps and can be
  removed at any time.
- Avatars are uploaded straight to Cloudinary with a short-lived signed
  signature; the API secret never reaches the browser.

## Operator checklist

- [ ] `SESSION_SECRET` and `SETTINGS_ENCRYPTION_KEY` are high-entropy, distinct
      and stored in a secret manager. Back up the encryption key: losing it makes
      stored provider settings unreadable.
- [ ] `PUBLIC_APP_URL` is the canonical HTTPS origin.
- [ ] `ADMIN_CIDR_ALLOWLIST`, `OPS_CIDR_ALLOWLIST` and `DEVICE_CIDR_ALLOWLIST`
      are set to real ranges, and `TRUST_PROXY` matches the proxy hops.
- [ ] `OWNER_BOOTSTRAP_TOKEN` was used once, then removed from the environment.
- [ ] Every administrator has an authenticator app enrolled.
- [ ] `OPS_SECURITY_EMAIL` is a monitored mailbox.
- [ ] SMTP/SMS credentials are entered in the admin console, not in `.env`.
- [ ] Backups are scheduled and restore has been rehearsed (`npm run backup`).
- [ ] `.env` is git-ignored and has never been committed.

## Known limitations (prototype)

- The firmware sketch disables TLS certificate validation so it runs against a
  self-signed local deployment. Pin the API root CA before any real use.
- Local-database mode uses a SQLite file on disk; use Turso for a hosted
  deployment and back it up.
- There is no intrusion detection, no WAF and no SIEM integration.
- The rotating ops credential is emailed; a hardware second factor would be
  stronger, and the TOTP requirement is the minimum bar.
